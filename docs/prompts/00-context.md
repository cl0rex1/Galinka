# Общий контекст для ИИ-агентов

Прочитай этот файл целиком до начала любой задачи в Galinka. Промпты в этой папке ссылаются на него и не повторяют его.

## Что это за проект

Galinka — мессенджер для своего круга: личные чаты, группы до 100 человек, голосовые, кружки, фото и файлы. Сервер ставит сам владелец, регистрация по приглашению. Поведение и вид повторяют Telegram. Пользователи пишут по-русски, интерфейс на русском.

- **Клиент:** React 19, TypeScript, Vite, `src/`. Один CSS без фреймворков: `src/styles.css` подключает модули `src/styles/NN-*.css`, все значения берутся из `tokens.css`.
- **Сервер:** Node.js 24, Express 5, PostgreSQL, `server/`. Почти всё API лежит в `server/index.ts`. Push описан в `server/push.ts`, голос в `server/audio.ts` и `server/transcription.ts`, медиа в `server/media.ts`, превью ссылок в `server/previews.ts`, бот Неля в `server/nelya.ts`.
- **Схема базы:** нумерованные миграции `server/migrations/NNN-*.sql` применяются при старте (`server/migrate.ts`). Новая миграция получает следующий номер. Старые миграции не правятся. Список миграций проверяет `tests/ops.test.ts`, его нужно обновить.
- **Живые обновления:** PostgreSQL LISTEN/NOTIFY и SSE, на клиенте `src/useSync.ts` и `src/useLiveMessages.ts`.
- **Android:** Capacitor плюс Java в `android/app/src/main/java/me/quiby/galinka/`: уведомления, ответ из уведомления, обновления APK.
- **Компьютер:** Electron, `desktop/main.cjs` и `desktop/preload.cjs`. Связь с интерфейсом идёт через `window.galinkaDesktop` (`src/desktop.d.ts`).
- **Демо-режим:** `/app?demo=1` работает без сервера. `src/demo.ts` повторяет API в браузере, и на нём держится большинство браузерных тестов. Каждое новое или изменённое поведение API нужно повторить в `demo.ts`, иначе демо и тесты разойдутся с сервером.

## Где что лежит в клиенте

- `src/App.tsx` — оболочка: разделы, открытый чат, окна, обработчики сообщений.
- `src/useConversation.ts`, `src/useComposer.ts` — переписка (загрузка, прокрутка, переходы) и поле ввода (черновики, вложения, отправка).
- `src/MessageList.tsx`, `src/MessageMenu.tsx`, `src/MessageText.tsx` — лента, меню сообщения, разметка текста.
- `src/ChatList.tsx`, `src/ChatInfo.tsx`, `src/ChatMedia.tsx`, `src/Settings.tsx` и соседние — экраны.
- `src/ui.tsx` — общие примитивы: `IconButton`, `Modal` (шторка на телефоне), `Confirm`, `usePresence`, меню на `<details>`, `useTabIndicator`, `motionAllowed`.
- `src/gestures.ts` — жесты: ответ свайпом, «назад» от края (`EdgeDrag`). `src/layout.ts` — условие телефона.
- `src/motion.tsx` — настройка «Меньше анимации» и анимация смены значения.

## Правила работы

1. **Сначала прочитать, потом менять.** Найди все места, где используется функция или таблица, которую трогаешь. Ошибку исправляй в общем месте, а не в одном вызове.
2. **Минимальная правка, которая работает.** Не добавляй зависимостей, абстракций и настроек «на будущее». Сначала проверь, нет ли уже готового помощника в коде.
3. **Интерфейс по дизайн-системе.** Перед любой правкой вёрстки прочитай [`docs/DESIGN.md`](../DESIGN.md): токены, роли размеров и скруглений, правила движения, жесты, где лежат стили. Новые стили кладутся в модуль своего компонента, а не в файл с номером версии.
4. **Тексты интерфейса** пишутся по-русски, регистр как в предложении. Кнопка называет действие глаголом. Ошибка объясняет, что делать дальше. Пустой экран говорит, что здесь появится.
5. **Безопасность.** Каждый запрос к чату проверяет членство (`member`, `lockedMember`). Файлы отдаются только участникам. SQL пишется только с параметрами. Ввод проверяется через `zod`. Никаких секретов в коде и логах.
6. **Версии и релизы.** Номер версии, релизный тег и публикация сборок меняются только по прямой просьбе владельца ([`AGENTS.md`](../../AGENTS.md)). Работа над задачами версии такой просьбой не считается.
7. **Коммиты** делаются, только когда об этом попросили.
8. **Задачи** берутся из [`TASKS.md`](../../TASKS.md). Сделанный пункт отмечается `[x]`, в скобках коротко пишется, как сделано и что не проверено.

## Проверка перед сдачей

```sh
npm run check
TEST_DATABASE_URL=postgres://…/galinka_test npm test
npx playwright test
```

- Серверные тесты (`tests/*.test.ts`, `node:test`) поднимают API на своём порту и ходят в отдельную тестовую базу. Без `TEST_DATABASE_URL` они пропускаются. Пример настройки есть в `tests/mentions.test.ts`.
- Браузерные тесты (`tests/browser/*.spec.ts`) запускают `npm run dev:web` и работают в демо-режиме или с подменёнными ответами API (`page.route`).
- Android: `cd android && ./gradlew :app:testDebugUnitTest :app:assembleDebug`, нужен JDK 21.
- Если на машине чего-то не хватает (ffmpeg, Postgres с русской локалью, телефона), так и напиши в отчёте и назови, что осталось непроверенным. Падения из-за окружения не выдаются за успех и не прячутся.
- Изменения интерфейса проверяются на экране: 390 × 844 и 1280 × 800, светлая и тёмная тема.
