# Промпт: проверка изменений

Ты проверяешь изменения в мессенджере Galinka: незакоммиченную работу, ветку или PR. Сначала прочитай [`docs/prompts/00-context.md`](00-context.md). Сам код не правь, пока не попросят: твоя задача — найти и доказать ошибки.

## Порядок

1. `git status` и `git diff` (или `git diff main...HEAD`). Составь список изменённых файлов и поведения.
2. Для каждой изменённой функции найди все её вызовы. Ошибка в общем месте ломает все вызовы, а не только тот, что в диффе.
3. Проверяй по списку:
   - **Доступ:** каждый новый обработчик проверяет членство в чате и права. Файлы и аватарки не отдаются посторонним. Нет SQL без параметров. Ввод проверяется через `zod`.
   - **Данные:** у новой миграции следующий номер, старые миграции не правились, `tests/ops.test.ts` обновлён. Удаление сообщения не оставляет файлов-сирот и не удаляет файл, который ещё используется в другом чате.
   - **Повторы и гонки:** повторная отправка с тем же `nonce` не создаёт дубль. Ответ, пришедший после смены чата, не попадает в другой чат.
   - **Демо:** новое поведение API повторено в `src/demo.ts`.
   - **Интерфейс:** значения взяты из токенов, стили лежат в модуле компонента, телефонная ширина проверена, жест продублирован кнопкой, «Меньше анимации» уважается ([`docs/DESIGN.md`](../DESIGN.md)).
   - **Тексты:** по-русски, регистр как в предложении, ошибка говорит, что делать дальше.
   - **Тесты:** новое поведение покрыто тестом, тест падает без исправления.
4. Запусти проверки из общего контекста и приложи вывод упавших.

## Отчёт

Найденное перечисли от самого серьёзного к мелкому. Для каждой находки укажи:

- файл и строку;
- что не так, одной фразой;
- сценарий: какие входные данные дают неправильный результат;
- насколько ты уверен: проверено запуском или выведено из кода.

Не включай вкусовые замечания без последствий. Если серьёзного не нашлось, так и напиши и перечисли, что проверял.
