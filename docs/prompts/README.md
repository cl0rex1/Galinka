# Промпты для ИИ-агентов

Готовые задания для других ИИ (Claude, Codex, Cursor и подобных), которые работают над Galinka параллельно или после этой сессии. Каждый промпт самодостаточен: агенту достаточно дать путь к файлу.

Как использовать: скопируйте в агента строку «Прочитай `docs/prompts/<файл>` и выполни». Общие правила проекта в [`00-context.md`](00-context.md) агент прочитает сам по ссылке.

| Файл | Что делает агент | Когда давать |
| --- | --- | --- |
| [`00-context.md`](00-context.md) | общий контекст: устройство проекта, правила, проверки, формат отчёта | читается всеми промптами |
| [`01-groups-channels-0.17.md`](01-groups-channels-0.17.md) | роли в группах, каналы, приглашения, сервисные сообщения | следующая версия |
| [`02-privacy-security-0.18.md`](02-privacy-security-0.18.md) | блокировка, двухфакторная защита, приватность профиля | после 0.17 или параллельно |
| [`03-interface-0.19.md`](03-interface-0.19.md) | единая «Назад», горячие клавиши, фоны, ширина панели, доступность | в любой момент |
| [`04-calls-0.20.md`](04-calls-0.20.md) | звонки: сначала план, потом код | когда решено, где будет TURN |
| [`05-platforms-0.21.md`](05-platforms-0.21.md) | iPhone, работа без сети, «Поделиться», трей | когда есть доступ к устройствам |
| [`06-bots-admin-0.22.md`](06-bots-admin-0.22.md) | команды Нели, API ботов, админка | в любой момент |
| [`07-code-review.md`](07-code-review.md) | проверка чужих изменений на ошибки | перед каждым коммитом или PR |
| [`08-design-review.md`](08-design-review.md) | проверка интерфейса на цельность и мобильную вёрстку | после крупных правок интерфейса |

Параллельно безопасно запускать задачи, которые трогают разные части: например, 0.18 (сервер, «Конфиденциальность») и 0.19 (стили, жесты). Двум агентам в одной папке лучше дать отдельные git worktree, чтобы они не перезаписывали файлы друг друга. `src/App.tsx`, `server/index.ts` и `src/demo.ts` меняет почти каждая задача, поэтому конфликты в них ожидаемы и решаются при слиянии.

Промпт обновляется, когда меняется устройство проекта: появляется новый модуль, общий помощник или правило проверки. Устаревший промпт хуже отсутствующего.
