# Промпт: 0.18.0 — профиль, приватность, защита

Ты работаешь над мессенджером Galinka. Сначала прочитай [`docs/prompts/00-context.md`](00-context.md) и [`docs/DESIGN.md`](../DESIGN.md), затем раздел «0.18.0» в [`TASKS.md`](../../TASKS.md).

## Задача

Сделай P1, затем P2 по порядку. Здесь безопасность важнее скорости: каждое правило доступа проверяется тестом.

## Что есть сейчас

- Аккаунт хранится в `users`. Сеансы — HttpOnly cookie (`sessions`), продлеваются при использовании. Список устройств с завершением сеанса лежит в `src/Security.tsx`.
- Приватность: `show_last_seen` и `group_invites` (`all`/`nobody`), экран `src/Privacy.tsx`.
- Проверка пароля и ограничение частоты запросов: `server/security.ts`.

## P1

1. **Блокировка пользователей.** Заблокированный не может написать в личный чат, не добавляет в группы, не видит статус «в сети» и аватарку, если так решено. Блокировка ставится из профиля человека и из меню личного чата, список заблокированных и разблокировка есть в «Конфиденциальности». Сервер проверяет блокировку при отправке, при добавлении в группу и при выдаче профиля. Сообщения заблокированного в общих группах остаются видны, как в Telegram.
2. **Двухфакторная защита.** TOTP (приложение-аутентификатор) и одноразовые резервные коды. При включении показываются QR, секрет текстом и коды. Включение подтверждается кодом. На входе после пароля спрашивается код. Секрет хранится только на сервере, коды хранятся в виде хешей. Попытки ограничены по частоте. Отключение требует пароль и код. Для TOTP не нужна внешняя зависимость: алгоритм RFC 6238 укладывается в `node:crypto`.

## P2

Уведомление о входе с нового устройства; автоматический выход с неактивных устройств; код-пароль или биометрия на вход в приложение (Android, Electron); удаление аккаунта и выгрузка своих данных; «О себе», дата рождения, ссылки; смена логина; статус с эмодзи; несколько фото профиля; приватность аватарки и поиска по логину; исключения «все, кроме…»; отключение отчётов о прочтении; несколько аккаунтов; секретные чаты со сквозным шифрованием; проверка файлов на вирусы.

Сквозное шифрование и несколько аккаунтов сначала оформи как отдельное предложение с планом в отчёте: это большие изменения модели данных.

## Ограничения

- Сообщения об ошибках не раскрывают, существует ли логин и какой из двух факторов неверен.
- Секреты, коды и токены не попадают в логи, телеметрию (`src/telemetry.ts`) и ответы API.
- Удаление аккаунта необратимо. Его подтверждают паролем, и окно прямо говорит, что пропадёт.
- Каждое новое поле API повторяется в `src/demo.ts`. Вход в демо-режиме не ломается.

## Готово, когда

- Серверные тесты покрывают блокировку (отправка, добавление в группу, видимость статуса), полный цикл 2FA (включение, вход с кодом, вход с резервным кодом, повтор того же кода, отключение) и ограничение частоты попыток.
- Браузерный тест проходит включение 2FA и вход в демо-режиме или с подменённым API.
- Все проверки из общего контекста проходят. В `TASKS.md` отмечены сделанные пункты.
